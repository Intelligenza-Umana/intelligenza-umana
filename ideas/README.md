# Future ideas

A lightweight incubator for possible future features, services, tools, governance rules and process improvements across Intelligenza Umana.

This is not a committed backlog, roadmap, policy or implementation instruction. Recording an idea creates no deadline or obligation. Existing governance and project-specific rules remain authoritative.

## How to use

1. Capture one idea per Markdown file using the [template](TEMPLATE.md), with a stable ID and descriptive filename.
2. Add it to the index. Record the problem, proposed approach, constraints, alternatives, risks and when it would be worth revisiting. Unknown details can stay open.
3. Review ideas when evidence or circumstances change, not on an artificial schedule.
4. Only after an explicit decision, promote an idea to an RFC, issue or project under the [engineering workflow](../docs/WORKFLOW.md); link that work here and update its status.
5. Keep rejected or superseded ideas with the rationale; do not silently turn proposals into rules.

Statuses: **Idea**, **Deferred**, **Under review**, **Accepted**, **Implemented**, **Rejected**, **Superseded**. Accepted means approved for planning, not completed.

Public repository: never include secrets, private applicant details, personal information or sensitive operational data. For sensitive proposals use an appropriate private channel.

See the [official roadmap](../docs/ROADMAP.md) and [governance](../docs/GOVERNANCE.md) for committed direction and current rules.
