# Onboarding
Start with README, license, manifesto, CONTRIBUTING and open issues. Choose an issue or propose a problem in the relevant repository; discuss the approach and submit a PR with verification. Write access only when necessary and agreed. No mandatory social group or personal registration.

## Your first contribution

1. Browse [open, unassigned good first issues](https://github.com/search?q=org%3AIntelligenza-Umana+is%3Apublic+is%3Aissue+is%3Aopen+no%3Aassignee+label%3A%22good+first+issue%22&type=issues).
2. Choose a task you can understand and verify. Documentation and reproducible testing count, even without code.
3. Comment on the issue with your approach; confirm scope before starting so work is not duplicated.
4. Fork, make a focused change and open a pull request with actual verification results and any limitations.

## Optional organization membership
Anyone can contribute without joining. If you wish to become a member, [open a membership request](https://github.com/Intelligenza-Umana/intelligenza-umana/issues/new?template=membership_request.md), or contact intelligenzaumana.lab@gmail.com privately. An organization owner reviews requests individually, without seniority requirements or guaranteed response times. Membership recognizes interest in sustained collaboration, reliability and alignment with IU principles; relevant experience or contributions outside IU can be sufficient even before a first IU contribution. No contribution quota or minimum number of members applies. Owners may also invite active contributors directly; acceptance is always voluntary. Membership alone does not grant write or administrative access to every repository; roles and permissions are agreed separately. An accepted request is followed by a GitHub invitation, which the applicant must accept. Do not publish personal details in issues.

## Discord roles

Sentinel is configured to assign Contributor to new human server participants. Member is a community recognition role assigned manually after the owner verifies the applicant's identity and accepted GitHub organization membership. The numeric Discord user ID in the public request is optional; applicants may provide it privately instead. Neither role automatically grants GitHub write or administrative permissions. Discord is optional.
