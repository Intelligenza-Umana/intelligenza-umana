# Security policy
Do not disclose exploitable vulnerabilities, secrets or personal data in public issues. Use GitHub private vulnerability reporting where enabled in the affected repository. If unavailable, request a private reporting channel without disclosing details. No dedicated security mailbox or response SLA has been established. Include affected versions, impact and safe reproduction steps in private reports. Avoid testing against systems without authorization. Each software repository must define supported versions and a verified reporting channel before public release.
